# 小红书 Skill + MCP

## 执行前先检查当前浏览器

每次发布或恢复任务，先发现当前浏览器的小红书标签页，检查登录账号及编辑/提交状态。优先复用已打开且账号匹配的创作中心；只有社区页时在同一浏览器进入创作中心。浏览器枚举超时时改查 Chrome 原生窗口和标签栏，不能据此认定没有登录。

已有可用登录页面时，不先启动独立浏览器、不要求用户再次扫码。专用工具能复用该页面就用专用工具，否则用 CUA。当前 publish.sh 使用独立 profile，不能接管日常 Chrome；仅在现有页面不可用或用户明确选择独立脚本时使用，确需登录再解释原因。不要复制登录凭证。中断恢复时先检查笔记管理和本地回执，避免重复发布。

## 固定动作的一键脚本

完成浏览器检查并选择独立脚本后，使用 `scripts/publish.sh`，不必让模型逐个点击。参数与原 MCP prepare 相同：account、title、content、按顺序排列的 images 绝对路径、mode（默认 draft）、定时任务的 scheduleAt。将已确认的原文写入该篇素材目录的 `发布任务.json`；保留正文换行，不自动重新创作。完整命令见服务 README。

- `sh scripts/publish.sh check /绝对路径/发布任务.json`：只检查素材与参数，不打开浏览器。
- 首次由用户在交互终端执行 `sh scripts/publish.sh login`，在独立窗口登录一次，之后沿用登录状态。
- `sh scripts/publish.sh run /绝对路径/发布任务.json`：默认存草稿。
- 已有当前篇公开发布授权时，run 后加 `--publish-authorized`，并使用 immediate 或 scheduled；无需重复询问用户。脚本不会调用 AI，依次上传、填写、读回、设置、单次提交并返回证据。

脚本在任务 JSON 旁创建 `.receipt.json`。同一回执的成功任务重跑只返回原结果；失败、提交中、未知结果或内容改变均停止，不重发。不能删除回执绕过检查；恢复前先核对实际页面与任务记录，准备阶段失败只有确认未提交并处理残留编辑器后才可另建任务。跨任务文件仍须检查既有发布记录，不能用换文件名重复发布。

页面变化、登录失效、验证码交回人工或 AI；固定等待都有上限。当前一键流程通过替身与协议测试，独立浏览器真实上传、草稿和公开提交仍需实际任务验收。原生 CUA 于 2026-09-09 发布成功的记录不代表此脚本已经实测。发布成功仅表示平台已接收，审核通过需单独核对。

若本机服务不存在或工具规则限制脚本控制浏览器，使用下方 MCP 流程或可用的 CUA，不绕过环境限制。脚本共享服务目录锁，不与 MCP 同时运行。移动服务目录时设置 `XHS_PUBLISHER_DIR`。


选择独立 MCP 流程后调用 xhs_status，确认用户在独立浏览器完成登录，确认预期账号。登录凭证不写进对话或配置。所有上传图片必须是MCP服务所在机器能读取的绝对路径。

用户提供文件夹时找到正式图片和文案，按页码排列，封面首位；内部说明不上传。发布前整理正文：开头承接封面、具体场景和收益，2–3个真实亮点，短段落与空行，少量表情导航，一个相关互动问题，3–6个相关话题。保留事实边界，不伪造体验或声称保证爆款。正文中的话题按普通文本保留，当前服务不自动建立平台话题实体。

1. 调用 xhs_prepare，传 account、title、content、images 和 mode。mode 默认为 draft；只有用户授权发布才选择 immediate 或 scheduled。定时使用带时区的 ISO8601。
2. 阅读返回的任务编号、内容、图片摘要和截图，确认输入及排版。prepare 不发布。
3. 使用同一次 prepare 的 jobId 和 digest 调用 xhs_commit。无需在已有明确授权时额外索取确认。用户尚未授权时停在准备结果。
4. 用返回的 state 区分 draft、published、scheduled、unknown。过期时间由服务转成 draft，不能改成立即发布。
5. unknown/submitting 状态不得新建同内容任务重试。先用 xhs_job 和实际页面检查是否已发出，必要时由用户人工核对。服务重启后不要猜测浏览器仍指向同一编辑器。

草稿存于该服务的独立浏览器目录，不是手机同步草稿。只描述实际证据；UI变化、登录过期和验证码可能阻断流程。当前版本完成状态机与协议测试，真实网页适配需要部署后验收。不能把工具无报错等同于发布成功。
